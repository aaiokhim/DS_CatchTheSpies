# p2_forum_boarding

Анна Иохим. Источники: профили форума часто летающих пассажиров (`FrequentFlyerForum-Profiles.json`, 568 МБ) и посадки на рейсы Аэрофлота (`BoardingData.csv`).

## Запуск

```
python3 participants/p2_forum_boarding/src/pipeline.py
python3 participants/p2_forum_boarding/src/pipeline.py --skip-parse     # без долгого разбора JSON
python3 participants/p2_forum_boarding/src/pipeline.py --only anomalies # один этап
```

Скрипт состоит из четырёх этапов:

1. parse - JSON читается потоково через ijson, по одному профилю, иначе файл не помещается в память. Каждый профиль раскладывается на четыре таблицы: профили, карты лояльности, перелёты, документы. BoardingData очищается и приводится к одному формату.
2. export - CSV-копии таблиц и общий файл перелётов форума и посадок.
3. anomalies - 15 проверок внутри моих источников.
4. identity - таблицы ключей, которые сдавались на этапе интеграции.

## Что получается

`output/processed/` (в репозиторий не входит, получается запуском):

| Таблица | Одна строка | Строк |
|---|---|---|
| `forum_profiles` | профиль форума | 66 592 |
| `forum_loyalty` | карта лояльности профиля | 88 827 |
| `forum_flights` | перелёт, отмеченный на форуме | 1 308 987 |
| `forum_documents` | документ из профиля (на форуме их нет, таблица пустая) | 0 |
| `boarding_clean` | посадка из BoardingData | 155 147 |
| `link_candidates` | пара «профиль форума - посадка» с тем же именем, рейсом и датой | 26 014 |
| `all_travel_events` | перелёты форума и посадки в одной таблице | ~1,46 млн |

`intermediate/anomalies/` - результаты проверок, по файлу на проверку, и `anomalies_report.md` с итогами:

| Файл | Проверка |
|---|---|
| `F1_card_shared_by_profiles` | одна карта у нескольких профилей форума |
| `F2_same_name_many_profiles` | одно имя у многих профилей |
| `F3_several_cards_same_program` | несколько карт одной программы в профиле |
| `F4_origin_equals_destination` | рейс из города в тот же город |
| `F5_same_day_unconnected_flights` | в один день перелёты, не стыкующиеся по городам |
| `F6_too_many_flights_profile` | слишком много перелётов в профиле |
| `F7_duplicate_flight_in_profile` | один перелёт отмечен дважды |
| `B1_document_different_people` | один документ у разных людей |
| `B2_person_many_documents` | у человека несколько документов |
| `B3_document_two_flights_2h` | по одному документу два рейса с разницей меньше 2 часов |
| `B4_ticket_shared` | общий билет |
| `B5_impossible_age` | невозможный возраст |
| `B6_too_many_flights_document` | слишком много рейсов по документу |
| `X1_profile_linked_to_many_documents` | профиль форума связан с несколькими документами |
| `X2_destination_mismatch` | город назначения на форуме и в посадке не совпадает |
| `persons_flags` | сводка проверок по людям |

Буквы здесь - коды моих локальных проверок, они не связаны с категориями признаков в `analysis/`.

`intermediate/integration_handoff/` - таблицы ключей для этапа интеграции (профили и карты форума, ключи и конфликты документов BoardingData). В репозитории оставлен только отчёт `identity_qa.md`, сами таблицы получаются запуском.

`samples/` - примеры всех этих таблиц. `reports/quality_report.md` - пропуски, дубликаты и форматы.

## Что нашлось

- На форуме нет ни одного документа, а у половины профилей (около 33 тысяч) не указано имя.
- В BoardingData примерно у половины записей нет PNR и билета (`Not presented`). `Baggage = None` означает «без багажа», это не пропуск.
- Карта FB 139888197 есть у двух профилей форума, один из них без имени.
- Документ 8248013778 у двух разных людей: Гордей Глебов и Рамиль Буров.
- Коды аэропортов в источниках форума переводятся в верхний регистр, поэтому битый код ngo (Конго) отличается от аэропорта NGO (Нагоя) только по городу.
